WorldGen v2 — 3D noise-graph world generation

Design spec for the rewrite of the world generator in Assets/Engine, written for a coding agent and for the owner's review. Minecraft Java 1.18 and later is the reference for the overall method; where v2 differs or adds something, the spec marks it as its own extension. Nothing in this spec is built yet.

0 · How to use this spec

  • Status. Phase V0: this spec is the design, and no runtime code exists. The owner's decisions of 2026-11-21 (DEC-125…138, §18) are binding. The agent defaults (AD-01…25, §19) fill the gaps the decisions leave open; they stand unless the owner changes them while reviewing this spec.
  • Relation to WorldGenSpec.html. Everything else there stays in force: Part E (performance, scheduler, culling, lighting), rotated voxels, tree species, the palette and the engine cleanup. §20 checks every earlier decision against v2.
  • Ground rules. The rules R1–R8 of WorldGenSpec.html §2 apply unchanged. In short: keep layers and dispose every native container (R1); Burst-compatible code without virtual dispatch (R2); every generated value is a pure function of seed, position and settings (R3); no silent tuning (R5); name real sources and mark own extensions, never invent a source (R6); no spec IDs, phase names, dates or history in code or in anything the Editor shows (R8).
  • Requirement keywords: MUST is mandatory; SHOULD is strongly recommended (deviate only with a reason stated in the commit or PR); MAY is optional.
  • IDs.   • Placeholders. Box edges, shares, wavelengths, depths, thresholds and every value called a start value are placeholders. The owner sets them with the preview window, the sweep and the world report; the agent must not tune them on its own (R5).
  • Read order: §1 → §2 → the section of the current phase (§16 points to it) → §17 for its tests and measurements. Before any benchmark, timing or build batch the agent asks the owner first, so the Editor can be focused (§17.5).
Part A Design

1 · Goals & scope

1.1 Goals

The owner's priorities for v2 are performance, moddability, and an interesting, continuous world. In practice:

  1. One generator built like Minecraft's 1.18+ generator: climate parameters from noise, a full 3D terrain density, biomes picked by parameter boxes, surfaces by rule lists, noise caves (DEC-125…134).
  2. Data, not code: noises, terrain shape, biome placement, surfaces and caves are data: a noise graph, biome files and rule lists. Tuning and mods change data only (DEC-126, GameSpec GAME-MOD-04).
  3. A continuous world: biomes follow large, smooth climate fields and never read the column height, so they change slowly and keep their place on slopes (DEC-127).
  4. Fast: at most 7.2 ms per chunk on the benchmark row (DEC-129); the 120 fps goal at p95 is unchanged (DEC-104).
  5. Checked, not hoped for: a validator rejects bad layouts before a world is built, and a world report measures the look targets on fixed seeds (§13).

1.2 Problems of v1 and how v2 answers them

The common root of the v1 problems: the 6D classifier read the column height, and every problem needed its own tuning round (the last one was PR #81). v2 removes the height from the biome choice and checks the layout before it is used.

1.3 Constraints

  • Frame rate: 120 fps at p95 with no micro-stutters the player notices (DEC-104). Generation runs in Burst jobs under the scheduler's per-frame budget (DEC-105, DEC-116) and adds no main-thread work.
  • Cost: at most 7.2 ms per chunk on the benchmark row ChunkJob.Run Terrain-first, DistanceBlend, flora, caves on (DEC-129: +25 % over 5.75 ms, the row's value on master on 2026-11-21).
  • Small hot loops: extra code inside one big pass once slowed the whole pass by 35 % (the PrepareChunkMaps case). New work goes into its own pass, and every change is measured.
  • Pure function: every voxel, biome id and flora placement is a pure function of (seed, position, settings) (R3). Chunk borders and padding agree bit for bit.
  • Burst and memory: FloatMode.Strict; no managed types or virtual dispatch in jobs; no Allocator.Domain inside a job (DEC-103). Scratch memory is allocated once per job, not per column, because Allocator.Temp memory inside a job is freed only when the job completes.

1.4 Signed-off targets that v2 keeps

  • The massif ranges of candidate A (DEC-108) and the points of the third world tour (DEC-109): draw distance 12, fog off, fallen logs only where their tree grows.
  • The ten biomes and their palette: Plains, Desert, Mountain, Forest, Ocean, Taiga, Savanna, Badlands, Jungle, Swamp, with the extended Kenney tiles and voxels.
  • Caves on everywhere (DEC-61) and the same in every biome (DEC-58), with ores, lava and bedrock (DEC-59).
  • Flora per biome: species, densities, groves, clearings, boulders and fallen logs (DEC-30…33, 45, 83, 84, 91, 97, 98).
  • The preview window as the main tuning tool, and a report test as the tuning measure.
  • Sea level 124 (water fills y < 124) and the height limit 255.

1.5 Out of scope for v2.0

  • Biome-first. The owner: Biome-first will be a completely different world generator with its own settings and assets, out of scope for now. The v1 Biome-first code is deleted together with v1 at the switch (DEC-137).
  • Part III research tooling (parked with Biome-first).
  • Aquifers, cave biomes and flora under overhangs: optional Phase V8 (§16).
  • Structures, fluid simulation, and persistence changes beyond the generator version and the settings hash (§15).
  • A graphical node editor for the noise graph (AD-19).

2 · Architecture

2.1 Overview

A chunk (32 × 256 × 32) is generated in nine passes. P1–P3 work on columns, P4–P5 on voxels, P6–P9 finish the chunk. The noise graph (§3) supplies every noise-derived value; biome files and rule lists supply the rest. The terrain does not depend on the biomes: P4 needs only P1, so biome changes never move the ground.

3 · Noise graph

3.1 What it is

Minecraft 1.18+ computes its terrain from density functions: where the final density is above 0 the default block is placed (Minecraft Wiki, “Noise router”, “Density function”). v2 uses the same idea with its own node set: a data-defined graph of noises and operations with named outputs (DEC-126). The graph replaces v1's fixed climate fields, terrain splines and cave noises.

3.2 Data

  • Noises: name, kind (2D or 3D simplex), octaves, base wavelength, lacunarity, gain, amplitude. The seed of a noise is a hash of the world seed and the noise's name, so adding a noise never shifts the others.
  • Nodes: an operation, its inputs (nodes or noises) and its constants.
  • Outputs: named nodes the generator reads (§3.6).
  • The graph is an asset with a JSON form (sorted keys), used by mods and by the settings hash (§15).

3.4 Compiler

The compiler turns the graph into flat programs, one for the 2D outputs and one for the 3D outputs: topological order, constant folding, common subexpression elimination and register allocation. Every node has an interval rule: bounds of its output from bounds of its inputs (a noise's bound comes from its octave amplitudes). The bounds drive the slab skipping (§5.4), the wetness early-out (§6.5) and parts of the layout validator (§6.6).

3.5 Interpreter

A batched Burst loop: one switch per instruction, and inside each case a loop over lanes, which Burst can vectorise. 2D lanes are one row of the padded corner lattice. 3D lanes are the active y corners of one corner column (at most 33 with cell height 8). Scratch: 64 registers × 33 lanes × 4 bytes ≈ 8.4 KB per worker.

3.7 Limits and fallback

Limits (start values): at most 512 instructions, 64 registers and 64 noises per graph. The graph validator rejects cycles, unknown names, missing required outputs and graphs over the limits, and names the file and node.

V1 measures the interpreter against hand-written Burst code for the same graph (v1's climate fields). If the overhead is above +15 % (the top of the +5–15 % estimate given with DEC-126), an Editor step generates C# Burst code for the shipped graph; the interpreter stays for mods and the preview.

4 · Parameters

4.1 The six parameters

As in Minecraft 1.18+ (Minecraft Wiki, “Biome”, “World generation”): temperature, humidity, continentalness, erosion, weirdness and depth, with peaks and valleys derived from weirdness. The start noises use v1's effective wavelengths, so the first v2 world has v1's climate scale (AD-10).

The wavelengths are the shipped v1 asset's values divided by its climate frequency scale 0.85 (T 4000, F 3200, C 3200, E 1600, W 1000).

4.2 Range and independence

  • Every parameter lies in [−1, 1] (AD-05). v1 values in [0, 1] convert by 2v − 1; for example v1's freeze temperature 0.2 becomes −0.6.
  • v1 bent humidity and temperature with continentalness (DEC-06). v2 drops that coupling (AD-04): the parameters are independent noises, which keeps the boxes easy to read. The graph can add a coupling back as data.

4.3 Bands (start values)

  • C, after Minecraft's bands: deep ocean −1…−0.455, ocean −0.455…−0.19, coast −0.19…−0.11, near inland −0.11…0.03, mid inland 0.03…0.3, far inland 0.3…1.
  • PV, after Minecraft's slices: valleys −1…−0.85, low −0.85…−0.2, mid −0.2…0.2, high 0.2…0.7, peaks 0.7…1.
  • T and F: five bands each at the 20 % quantiles of the land columns, measured by the sweep tool (AD-11). With a T spread of about 0.35 the edges lie near −0.29, −0.09, 0.09 and 0.29.
  • E: the massif footprint (E ≤ −0.38) and the terrain splines. Minecraft uses seven erosion levels; v2 starts with fewer and adds levels where a box or a spline needs them.

4.4 Sampling

The 2D outputs are computed at stride 4 on the padded corner lattice and interpolated bilinearly per column; with wavelengths of 192 blocks and more nothing visible is lost. An output with shorter wavelengths (the blend's border noise has 28) carries a per-column flag and is evaluated for every column instead. A column's biome comes from its interpolated parameters (AD-07), so it is smooth at every scale and the same in a chunk and in its neighbour's padding.

W2-NG-07MUSTClamp the five climate outputs and PV to [−1, 1].
W2-NG-08MUSTSample the 2D outputs on a world-aligned stride-4 lattice (points at multiples of 4 in world coordinates) and interpolate per column; outputs flagged per column are evaluated for every column.

5 · Terrain density

5.1 Form

Full 3D density (DEC-125). As in Minecraft, a voxel is terrain where the density is above 0. The split into a smooth part from splines and a 3D noise term that fades out underground is an own extension.

density(x, y, z) = K · (S + J · P − y) / 64  +  w(y) · N3(x, y, z)      then the top slide

S   = 124 + O(C, E, PV)        offset spline: the base height
J   = J(C, E, PV) ≥ 0          jaggedness spline: how much the peaks add
P   = (1 − |n|)²               peak noise, wavelength 192 (start)
K   = K(C, E, PV) > 0          factor spline: large = flat, plain-like; small = overhangs
N3  = 3D fbm noise with amplitude A
w   = 1 above preliminary_surface − 16, fading smoothly to 0 at preliminary_surface − 32
top slide: density pulled to −1 by a smooth step between y 223 and 255

preliminary_surface = S + J · P
Δmax = 64 · A / Kmin           the furthest the 3D noise can move the real surface
                               away from preliminary_surface (Kmin from the interval rules)

Below preliminary_surface − 32 the rock is plain solid and N3 is not evaluated (AD-24). The top slide replaces v1's soft height limit.

5.2 Terrain shape (start)

New Minecraft-like terrain built from scratch (DEC-128); no bit-identical anchor to v1. The splines are data and start roughly like this:

  • Offset over C: below sea level in the ocean bands, crossing sea level in the coast band, rising inland. From the near-inland band on the ground stays above sea level except in river valleys, which keeps lowland biomes such as Jungle dry (§6.4).
  • Erosion: high E flattens, low E raises. Low E in the mid and far inland bands makes the massifs; v1's massif shape (on C and E with PV inside, peak wavelength 192) is the start, and the re-tune target is the ranges of candidate A (DEC-108).
  • PV: hills on the peaks slices, valleys on the valleys slice; the valleys slice also makes the rivers (§9.2).

5.3 Cells and interpolation

The density is evaluated on a world-aligned corner lattice and interpolated trilinearly per voxel. Minecraft also evaluates its density on coarse cells and interpolates (Minecraft Wiki, “Noise router”); its exact cell size is not claimed here. v2 starts with cells of 4 × 8 × 4 blocks (AD-06): 9 × 33 × 9 = 2,673 corners per chunk. Cells of 4 × 4 × 4 (9 × 65 × 9 = 5,265 corners) are measured in V2 and used only if 4 × 8 × 4 looks blocky on steep faces.

Terrain and cave densities are interpolated separately, because P5 must tell terrain air (water below sea level) from carved air (dry, §9.1).

5.4 Skipping

  • Slab bounds. For each corner column and 32-block slab, the interval rules bound terrain_density and cave_density over the slab. A terrain bound below 0 makes every corner of the slab non-terrain; a terrain bound and a cave bound both above 0 make every corner solid. Corners whose sign is known are not evaluated.
  • Uniform cells. Trilinear interpolation is a convex combination of the 8 corners, so when all 8 corners have the same sign, every voxel of the cell has that sign. Such cells are filled without per-voxel interpolation. The test is exact, not an estimate.

5.5 Overhangs and floating pieces

The 3D noise makes overhangs, arches and now and then a floating piece. v2.0 allows them. The world report counts floating solid pieces and the overhang share; the owner judges them in the V2 tour.

5.6 Heightmap

The chunk's heightmap is the top of the terrain: the highest voxel of each column with terrain density above 0, before carving (DEC-60 and v1's CAV-04 kept). Light, the camera, spawn, flora and the preview read it.

W2-DEN-02MUSTPlace lattice corners at world-aligned positions (multiples of the cell size), so chunks agree at their borders.

6 · Biomes

6.1 Boxes

Per-biome parameter boxes (DEC-127), in Minecraft's format: a biome is placed by intervals per parameter (Minecraft Wiki, “Biome”). Each biome file holds one or more boxes; a box is an interval for T, F, C, E and W plus a depth interval. v2.0 evaluates depth 0 only; the depth interval is reserved for cave biomes (V8). A biome can hold several boxes, for example one inside the massif footprint and one outside.

6.2 Choosing a biome

  • A column's parameters lie in at most one box: overlapping boxes are an error (AD-09).
  • A point in no box takes the nearest box. The distance is the sum of the squared distances to each interval (0 inside it), unweighted; ties go to the order of the BiomeSet. Minecraft also takes the closest box outside all boxes; its exact distance form is not claimed here.
  • The choice reads only the climate parameters at depth 0, never the column height (AD-07).

6.3 Compiled lookup

The boxes compile into a grid whose lines are the box edges, so every grid cell lies inside one box or in a gap; one binary search per parameter finds the cell. A gap cell stores the boxes that can be nearest somewhere in the cell, and the column picks among them. If the grid would exceed 220 cells, a tree replaces it. The lookup gives the brute-force result on every sampled point and costs at most 0.2 ms per chunk including padding.

6.5 Wetness and the dry-column rule

  • Wet column: the terrain is air at y 123, the top water layer (AD-08). The value at y 123 comes from the two corner layers around it (y 120 and 128 with 4 × 8 × 4 cells), interpolated the same way as in P4.
  • Early-out: a corner column with preliminary_surface − 128 > Δmax is surely dry; one with 120 − preliminary_surface > Δmax is surely wet. Only corner columns in between evaluate the two layers.
  • Dry-column rule: when the lookup gives a water biome (a flag in the biome file; only Ocean in the shipped set) on a dry column, the column takes the nearest land box instead, by the same distance rule. A land biome on a wet column keeps its biome (lakes, rivers).
  • The near_water rule condition (§7.2) uses the same wet flags on the stride-4 corner grid: a wet column within 16 blocks, probed every 4 blocks (DEC-44).

7 · Surface rules

7.1 Lists

Minecraft chooses surface blocks with one rule tree of conditions and sequences (Minecraft Wiki, “Surface rule”). v2 uses rule lists (DEC-133), which are easier to read and to extend by mods:

  1. global-before (for example snow),
  2. the list of the column's surface-source biome (§12; AD-25),
  3. global-after (for example a mod's fallback).

For each solid voxel the lists run in this order and the first rule whose condition holds acts. When no rule matches, the voxel keeps the default block (stone). A rule is a condition and an action. Rules see the final solid mask after P4, so cave walls and the undersides of overhangs are surfaces like any other.

7.5 Cost

  • Column-constant conditions are evaluated once per column into a bitmask.
  • The rule depth R is the deepest stone-depth bound of any rule, noise included. A voxel that lies more than R below the nearest non-solid voxel above it and more than R above the nearest one below it is an interior voxel.
  • Interior voxels take the column's interior plan: the rules resolved once per column for interior voxels, at most four y ranges, each with a block or a bands action. Only voxels near a surface run the full lists.

7.6 Rule validator

  • Unknown blocks, biomes, noises or outputs: error, with the file and rule named.
  • A condition that can decide interior voxels must be column-constant or a y threshold; anything else is an error.
  • The caverns' cover (§10.2) must be at least the top rules' margin plus R, so a covered cavern never opens inside the top rules' reach: error otherwise.
  • A rule after an unconditional rule in the same list can never act: warning.

8 · Snow, ice & tree line

8.1 Effective temperature

T_eff(x, y, z) = T(x, z) − L · max(0, y − 124) + wobble(x, z)

Snow and ice follow the climate temperature cooled with height, in every biome (DEC-130, DEC-131). This is an own extension: Minecraft uses each biome's base temperature, lowered with height above a fixed level (Minecraft Wiki, “Biome”). It has the form of v1's SurfaceCover temperature (GEN-36): climate temperature, a lapse above the water and a freeze noise once per column. T and the wobble are column values; only the lapse is per voxel.

8.2 Snow

The snow rule sits in global-before: a floor voxel that is dry and sky_open, with Teff < Tsnow, in a biome without the never-snow flag, takes the snow block (shipped: Snow; a biome file may name its own).   • L = 0.0055 per block; Tsnow = −0.473; wobble ±0.033 (±6 blocks), wavelength 64.
  • The snow line is ys(T) = 124 + (T − Tsnow) / L.

8.3 Ice

In the fluid pass, the top water layer (y 123) freezes where Teff < Tice = −0.6, v1's freeze temperature 0.2 in the v2 range (AD-13). Since Tice < Tsnow, every frozen shore also carries snow down to the water, as v1's GEN-36 asks, and the wobble gives the ice a ragged edge. The FreezesWater flag goes (DEC-131 replaces DEC-65).

8.4 Never-snow biomes

  • A biome file may carry a never snows flag (shipped: Badlands, Desert, Savanna, Jungle). The snow rule and the ice skip a column whose surface-source biome has it, so snow and ice agree at a border.
  • The flag is a filter, not the main tool: with the starting layout the hot band's snow line already lies above the terrain. The layout validator warns when a never-snow biome could reach its snow line: when ys(lowest T of its boxes) − 6 lies below the highest ground of its boxes, bounded by the interval rules. Such a biome would show a hard snow edge at its border.
  • The world report checks snow in never-snow biomes (0) and counts hard snow edges.

8.5 Tree line and meadow

  • Ttree = Tsnow + 15 · L ≈ −0.39: the tree line lies 15 blocks below the snow line, with its own wobble of ±8 blocks at wavelength 64 (v1's VEG-51 values). At T 0 it lies at 195, as in v1 (DEC-86).
  • Flora rules with StopsAtTreeLine stop above it; soil rules grow neither on snow nor on bare stone (VEG-52, unchanged).
  • Below the tree line a dry floor takes its biome's meadow block (GEN-44). On Mountain: meadow, then bare stone above the tree line, then snow above the snow line (DEC-88).

8.6 What changes against v1

  • DEC-65 is reversed. Snow and ice are no longer limited to Mountain: the coldest lowland (T below −0.473, about 9 % of the land with a T spread of 0.35) is snowy down to the sea and has ice on its water, and cold Taiga and Plains hills are snowy above about 156.
  • DEC-96's snow allowance in Badlands goes: Badlands never snows.
  • The fixed snow line (210 ± 6) and tree line (195 ± 8) become climate lines that pass through 210 and 195 at T 0.

9.2 Rivers

Rivers are Minecraft's valleys (DEC-132): the valleys slice of PV (PV ≤ −0.85, which is |W| ≤ 0.05) gets a low offset in the terrain splines (Minecraft Wiki, “World generation”). In v2:

  • Where the land around is low, the offset spline lowers S in the valleys slice to 3–5 blocks below sea level, and the fluid rule fills the bed with water.
  • Where the land is high, the valley stays above sea level and dry: a gorge without water (AD-14). There is no water above sea level.
  • No River biome: a river column keeps its land biome (a land biome on a wet column keeps it, §6.5). The river output, clamp(1 − |W| / 0.05, 0, 1), lets rules and mods dress the banks and the bed.
  • Start: rivers about 600 blocks apart. Their width follows the slope of W at its zero line; V5 measures both.

10 · Caves, ores & lava

10.1 Form

Caves are noise terms of the density, the owner's pick “Minecraft-style noise caves” (DEC-134). The terms and their start shapes below are v2's own and start from v1's Phase K values:

cave_density = min(caverns, tunnels, passages, lava_pockets)        ≤ 0 carves
  • Caves carve solid terrain only, never water (§9.1), and never at y ≤ 2 (bedrock).
  • The graph gives caves no biome input: they are the same everywhere (DEC-58) and on everywhere (DEC-61).
  • Caves stay dry; aquifers are V8 (DEC-135).

10.2 Caverns

  • Shape: v1's halls (CAV-10, DEC-79). A 3D fbm at wavelength 96 across and 48 up, sampled at a position that two warp noises (wavelength 64) shift by up to 20 blocks, plus a detail octave (wavelength 28, amplitude 0.3) folded at its zero crossings (1 − 2|n| − 0.3).
  • Height band: y 4…90. The threshold rises towards the top of the band and falls towards its floor, so caverns close off at the top and are widest just above the floor (DEC-75, DEC-76). In the graph this is a y_gradient.
  • Mask: a 2D noise lets caverns form on about 15 % of the area. Its edge fades over 0.1 of mask value with a smooth step (DEC-67).
  • Cover: caverns carve only below preliminary_surface − Cover. Start: Cover = Δmax + 8, so at least 8 blocks of rock lie over a cavern (v1's Cover 8).
  • Entrances: an entrance mask on about 3 % of the land (v1's share) lifts the cover, so a cavern can open to the sky there: rare, large cave mouths (DEC-55). v1 used this mask for worm shafts; v2 has no worms.
  • v1's pillars go. A mod or a later round can add them back as a graph term.

10.3 Tunnels and passages

  • Tunnels: max(|a|, |b|) − r, with two 3D noises a and b (AD-15). A tunnel follows the line where both noises are zero, so it winds through the rock and crosses other tunnels and caverns. This is the spaghetti form that DEC-54 did not choose in v1; the owner's pick of noise caves now takes it.
  • Radius: r follows a slow noise. Start: at least 2.5 blocks, so the player can walk through.
  • Interpolation: a tunnel that is thinner than a cell is tall can fall between two corner layers and vanish or break into beads. With cells 8 high a tunnel needs a radius of about 4; with an own cave lattice of cells 4 high, 2.5 is enough. V6 measures both (AD-06).
  • Surface: tunnels have no cover and may break dry ground anywhere (DEC-77). They stop at water like every cave.
  • Passages (optional): the same form with a smaller radius under a mask. Off in the start graph.

10.4 Lava

  • Lava pockets (DEC-56): inside the lava mask (a 2D noise on about 40 % of the area, CAV-30), a flat 3D noise (wavelength 32 across, strongly squashed in y) carves in the band y 3…10 (CAV-31). The fluid rule makes their voxels at y ≤ 5 lava and those above air: a lava surface under a low air gap. The mask fades over 0.1 (DEC-67), and the pockets stay under the caverns' cover (DEC-68).
  • Lava level: every carved voxel at y ≤ 5 is lava, in every column (DEC-77, AD-02).
  • Lava emits light as before; the light job is measured again on lava chunks (CAV-50).

10.5 Connected caves

DEC-74's goal stays: no tunnel on its own. Noise tunnels are long lines that cross each other and the caverns, so they form networks without connector logic. The cave report checks this: the share of carved voxels in a sample window that belong to a component of at least 1,000 voxels or reach the window's edge (start target ≥ 95 %, a placeholder).

10.6 Ores

v1's ore veins stay (CAV-40, CAV-41, DEC-59): 16³ cells, hashed vein seeds and short random-walk blobs. The ore rules run in list order and each replaces only its host block (DEC-69). They now run after the fill and the surface rules (P6, AD-16), so they see the final blocks. Ores never replace air, so caves still expose veins in their walls, as in v1, where the ores came before the caves.

10.7 Bedrock

Unchanged (CAV-42): y 0 is always bedrock, y 1 and y 2 are bedrock where a 3D hash falls below 0.5 and 0.25.

What changes against v1: worms, connector worms, worm shafts and pillars go (DEC-134 replaces DEC-54, 57, 66, 70, 71, 73, 75 and 76). Tunnels now come from noise, the option DEC-54 left out. Caves near water follow DEC-78 (AD-03).

11 · Flora

11.1 Anchor

A column's flora anchor is the top of the terrain: its highest voxel with terrain density above 0 (§5.6). Flora grows there only when that voxel is not carved, and a tree only when the voxel under its trunk is solid (v1's CAV-04). v2.0 grows no flora on cave floors or under overhangs; that is an idea for V8 (AD-18).

11.2 Padding search

A tree anchored in the flora padding (11 blocks) is stamped by every chunk it reaches, so each chunk needs the anchors of its padding columns. The padding search evaluates a padding column's terrain density only between preliminary_surface − Δmax and preliminary_surface + Δmax, where its top must lie, from the same world-aligned corners. It therefore finds the voxel that the chunk owning the column finds. Cost: 0.1–0.3 ms (§2.4).

15 · Determinism & identity

  • Pure function: every voxel, biome id and flora placement depends only on the seed, the position and the merged data (R3). The jobs keep FloatMode.Strict and synchronous Burst compilation (GameSpec §3.7).
  • No transcendental functions: GameSpec §3.7 found the worms' sin, cos and atan2 to be the only functions in shipped generation without a cross-machine promise. They go with the worms. v2's nodes use only the four basic operations, min, max, abs, floor and sqrt, which IEEE 754 defines exactly.
  • Identity: a world stores generatorVersion 2 and the settings hash, a hash of the canonical JSON (sorted keys) of the merged data. Land that was never edited follows the generator; edited chunks are saved (the D2 save model).

20.4 Flags for the owner

These results change or reverse something the owner signed off. They stand with the v2 picks unless the owner says otherwise.

  1. DEC-65 is reversed (DEC-130, DEC-131). Snow and ice follow the climate in every biome without the never-snow flag: the coldest lowland (about 9 % of the land at the start values) is snowy down to the sea, cold Taiga and Plains hills are snowy above about 156, and cold shores freeze (§8.6).
  2. DEC-96's snow allowance is gone: Badlands never snows.
  3. DEC-54 is reversed (DEC-134). Tunnels come from noise, the form DEC-54 left out; worms, worm shafts and pillars go.
  4. DEC-78 holds over the cave design: water is never carved, so a cave can open a lake bed or the seabed and leave a wall of standing water. The world report counts the walls; CaveWaterMargin is the lever (AD-03).
  5. DEC-77 holds over the lava mask: every carved voxel at y ≤ 5 is lava in every column; the mask only shapes the pockets above (AD-02).
  6. DEC-06 is dropped: continentalness no longer bends temperature and humidity (AD-04).
  7. DEC-38: there is no height stage any more, because the terrain does not depend on the biome. DistanceBlend still costs about 1.5–2 ms for materials and flora.
  8. Tree line: v1's fixed line at 195 ± 8 becomes a climate line 15 blocks below the snow line, with its own ±8 wobble; at temperature 0 it still lies at 195 (AD-12).
  9. DEC-120, 121 and 123: their classifier values (the Badlands height floor, the class-height peaks, the Ocean flag) are not carried over. The climate wavelengths of the shipped settings, which DEC-121 made larger, are only the start values of the sweep (AD-10). Their goals become world-report targets (§13.5).
  10. Part III research is parked with Biome-first (DEC-137): DEC-28 waits with it, and DEC-92 loses its subject.
  11. DEC-74's goal stays: no tunnel stands on its own; the cave report checks it (§10.5).

  14. Implausible pairs become an error of the layout validator instead of a preview overlay (§6.6).
