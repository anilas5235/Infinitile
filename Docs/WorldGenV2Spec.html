WorldGen v2 — 3D noise-graph world generation

Design spec for the rewrite of the world generator in Assets/Engine, written for a coding agent and for the owner's review. Minecraft Java 1.18 and later is the reference for the overall method; where v2 differs or adds something, the spec marks it as its own extension. The graph core (§3, Phase V1), the terrain density (§5, Phase V2) and the biomes and blend (§6, §12, Phase V3) are built; the rest is design.

0 · How to use this spec

  • Status. Phases V1–V5: the graph core (§3), the terrain density (§5), the biomes and blend (§6, §12), the surface rules with snow and ice (§7, §8) and the rivers (§9.2) are built beside v1, and H1 raised the build height to 512 (§5.7); next come the height phase H2 (§16), then V6a; the density generator is a world setting, and since V3 it is the shipped setting (DEC-167, a deviation from AD-22). The rest of this spec is the design. §2.4 and §3.7 hold the measurements, and “Built in” notes record where the build differs from the text. The owner's decisions (DEC-125…244, §18) are binding. The agent defaults (AD-01…48, §19) fill the gaps the decisions leave open; they stand unless the owner changes them while reviewing this spec.
  • Relation to WorldGenSpec.html. That spec stays the record of the shipped generator until the switch (Phase V7, §16). v2 replaces its Terrain-first biome selection (the classifier with class height), the Biome-first architecture, every blend method except DistanceBlend and None, and the worm caves. Everything else there stays in force: Part E (performance, scheduler, culling, lighting), rotated voxels, tree species, the palette and the engine cleanup. §20 checks every earlier decision against v2.
  • Ground rules. The rules R1–R8 of WorldGenSpec.html §2 apply unchanged. In short: keep layers and dispose every native container (R1); Burst-compatible code without virtual dispatch (R2); every generated value is a pure function of seed, position and settings (R3); no silent tuning (R5); name real sources and mark own extensions, never invent a source (R6); no spec IDs, phase names, dates or history in code or in anything the Editor shows (R8).
  • Requirement keywords: MUST is mandatory; SHOULD is strongly recommended (deviate only with a reason stated in the commit or PR); MAY is optional.
  • IDs. Requirements use the prefix W2-: W2-ARC architecture, W2-NG noise graph, W2-DEN terrain density, W2-HGT world height, W2-BIO biomes, W2-SRF surface rules, W2-CLM snow, ice and tree line, W2-FLD fluids, W2-RIV rivers, W2-CAV caves, ores and lava, W2-FLO flora, W2-BLD blending, W2-TOOL tooling, W2-MOD moddability, W2-ID identity, W2-PERF performance, W2-TST tests, W2-MIG migration. Agent defaults are AD-nn. Decision numbers continue the v1 list, so every DEC-nnn is unique across both specs.
  • Placeholders. Box edges, shares, wavelengths, depths, thresholds and every value called a start value are placeholders. The owner sets them with the preview window, the sweep and the world report; the agent must not tune them on its own (R5).
  • Read order: §1 → §2 → the section of the current phase (§16 points to it) → §17 for its tests and measurements. Before any benchmark, timing or build batch the agent asks the owner first, so the Editor can be focused (§17.5).
Part A Design

1 · Goals & scope

1.1 Goals

The owner's priorities for v2 are performance, moddability, and an interesting, continuous world. In practice:

  1. One generator built like Minecraft's 1.18+ generator: climate parameters from noise, a full 3D terrain density, biomes picked by parameter boxes, surfaces by rule lists, noise caves (DEC-125…134). From H2 Minecraft's generator is also the base of the look: its heights, terrain shape and mountain coverage are the starting point, and our changes build on it towards an Earth-like, continuous, beautiful world (DEC-231).
  2. Data, not code: noises, terrain shape, biome placement, surfaces and caves are data: a noise graph, biome files and rule lists. Tuning and mods change data only (DEC-126, GameSpec GAME-MOD-04).
  3. A continuous world: biomes follow large, smooth climate fields and never read the column height, so they change slowly and keep their place on slopes (DEC-127).
  4. Fast: at most 10 ms per chunk, the mean over the chunk classes of the benchmark fixture (DEC-147, DEC-235); the 120 fps goal at p95 is unchanged (DEC-104).
  5. Checked, not hoped for: a validator rejects bad layouts before a world is built, and a world report measures the look targets on fixed seeds (§13).

1.3 Constraints

  • Frame rate: 120 fps at p95 with no micro-stutters the player notices (DEC-104). Generation runs in Burst jobs under the scheduler's per-frame budget (DEC-105, DEC-116) and adds no main-thread work.
  • Cost: at most 10 ms per chunk: the mean over the chunk classes of the benchmark fixture, with everything on (caverns, tunnels, lava, ores, bedrock, flora, DistanceBlend; DEC-147, which replaced the 7.2 ms of DEC-129 with 8 ms, raised to 10 ms by DEC-235; §17.5). The old reference row ran a placeholder world without lava, ores or bedrock. The like-for-like v1 row is ChunkJob_Run_Caves_MsPerChunk: 6.33 ms with caves on, 4.82 ms with caves off (baseline 2026-11-19).
  • Small hot loops: extra code inside one big pass once slowed the whole pass by 35 % (the PrepareChunkMaps case). New work goes into its own pass, and every change is measured.
  • Pure function: every voxel, biome id and flora placement is a pure function of (seed, position, settings) (R3). Chunk borders and padding agree bit for bit.
  • Burst and memory: FloatMode.Strict; no managed types or virtual dispatch in jobs; no Allocator.Domain inside a job (DEC-103). Scratch memory is allocated once per chunk, never per column or cell, because Allocator.Temp memory inside a job is freed only when the job completes. Report and sweep jobs over large areas run through SlicedParallelFor (W2-ARC-03).

1.4 Signed-off targets that v2 keeps

  • The massif ranges of candidate A (DEC-108; replaced by Minecraft's scale in H2, DEC-213, DEC-219) and the points of the third world tour (DEC-109): draw distance 12, fog off, fallen logs only where their tree grows.
  • The ten biomes and their palette: Plains, Desert, Mountain, Forest, Ocean, Taiga, Savanna, Badlands, Jungle, Swamp, with the extended Kenney tiles and voxels.
  • Caves on everywhere (DEC-61) and the same in every biome (DEC-58), with ores, lava and bedrock (DEC-59).
  • Flora per biome: species, densities, groves, clearings, boulders and fallen logs (DEC-30…33, 45, 83, 84, 91, 97, 98).
  • The preview window as the main tuning tool, and a report test as the tuning measure.
  • Sea level 124 (water fills y < 124) and the height limit 255, until H2: from H2 on the sea is 127 and the terrain reaches y 383 in a world 512 high (DEC-210, DEC-211, §5.7).

1.5 Out of scope for v2.0

  • Biome-first. The owner: Biome-first will be a completely different world generator with its own settings and assets, out of scope for now. The v1 Biome-first code is deleted together with v1 at the switch (DEC-137).
  • Part III research tooling (parked with Biome-first).
  • Aquifers, cave biomes and flora under overhangs: optional Phase V8 (§16).
  • Structures, fluid simulation, and persistence changes beyond the generator version and the settings hash (§15).
  • A graphical node editor for the noise graph (AD-19).

2 · Architecture

2.1 Overview

A chunk (32 × 256 × 32; 32 × 512 × 32 from H1, §5.7) is generated in nine passes. P1–P3 work on columns, P4–P5 on voxels, P6–P9 finish the chunk. The noise graph (§3) supplies every noise-derived value; biome files and rule lists supply the rest. The terrain does not depend on the biomes: P4 needs only P1, so biome changes never move the ground. P2 runs the terrain part of the 3D program at the two corner layers next to sea level (y 120 and 128, derived from the sea level in code; with the sea at 127 they are still 120 and 128) for its wetness test (§6.5), and P4 reuses the chunk's own values of those layers. The padding table in §2.2 gives the area each value is needed over.

2.5 Levers

  • Lane-wise simplex: a simplex written for lanes, without a branch per sample; v1's SeededSimplex is scalar and branchy. Noise is nearly all of P1's and P4's corner cost, so this is the largest lever. Measured in V1 (§3.7).
  • Blend lattice at stride 4 (v2 starts at stride 2, AD-28): about half the kernel's cost; needs a look check of the borders (V3).
  • Cell size: 4×8×4 is the start (2,673 corners per chunk); 4×4×4 doubles the vertical corners and is measured in V2.
  • Skipping: the corner columns' y ranges and uniform cells (§5.4) are built in from V2.
  • Uniform biome cells: if the four corners of a 4 × 4 column cell lie in the same box, and no box that wins over it overlaps the bounding box of the four corners' parameters, all 16 columns get that biome: a box is convex and the parameters are interpolated bilinearly. The same holds for the wet flag when all four corners are surely dry or surely wet. Exact.

3 · Noise graph

3.1 What it is

Minecraft 1.18+ computes its terrain from density functions: where the final density is above 0 the default block is placed (Minecraft Wiki, “Noise router”, “Density function”). v2 uses the same idea with its own node set: a data-defined graph of noises and operations with named outputs (DEC-126). The graph replaces v1's fixed climate fields, terrain splines and cave noises.

3.2 Data

  • Noises: name, kind (2D or 3D simplex), octaves, base wavelength, lacunarity, gain, amplitude; a 3D noise may give its own wavelength along y (wavelengthY, default: the base wavelength). The seed of a noise is a hash of the world seed and the noise's name, so adding a noise never shifts the others.
  • Nodes: an operation, its inputs (nodes or noises) and its constants. The bounds of clamp, smoothstep and range_choice, the heights and values of y_gradient and the locations and derivatives of spline points are constants; every other operand may be a node. A node name may not be x, y or z and may not contain a dot, because messages name a field as node.field.
  • Outputs: named nodes the generator reads (§3.6).
  • The graph is an asset with a JSON form (sorted keys), used by mods and by the settings hash (§15).

3.4 Compiler

The compiler turns the graph into three flat programs: the 2D program (nodes that do not depend on y, run on the stride-4 column lattice), the corner program (the inputs of the interpolated markers, run at the lattice corners) and the voxel program (the nodes above the markers, run per voxel after the interpolation, only in cells the skipping leaves open). A per-column 2D output adds a column program, the 2D nodes it needs run on every column. There is one corner program per cell height in use. 2D values enter the corner programs exactly (corner columns are lattice columns) and the voxel program interpolated bilinearly per column, broadcast to every lane of a column. Each program gets topological order, constant folding, common subexpression elimination (on add and mul operand order only, never an algebraic rewrite that changes bits) and register allocation.

Exact values at the lattice: lerp(a, b, t) is a + t (b − a), so an interpolated value at a lattice column or corner height is the direct value bit for bit, except that −0 may come out as +0. Tests compare with that one exception.

The compiler does no float arithmetic in managed code (AD-30). Settings load runs in Mono in the Editor and in the player's runtime in a build, and managed floats can differ from Burst's (the reason for v1's GEN-16). Constant subgraphs, spline tangents and interval bounds are computed by running them through the Burst interpreter (FloatMode.Strict, compiled synchronously). Every bound except a constant's is widened by a margin of 1e-4 · max(1, m), with m the larger magnitude of its two ends (start 1e-4, as v1's SkipMargin; relative above 1, because a fixed 1e-4 is below the rounding of values in blocks such as a surface height near 200), so a bound that is one ulp off never makes the skipping wrong.

Every node has an interval rule: bounds of its output from bounds of its inputs. A noise's bound comes from its octave amplitudes; fbm divides by the amplitude sum, so its bound is its amplitude. spline: the hull of the bounds of its point values, widened by each cubic segment's overshoot (bounded from its tangents). shift: the bound of the noise it moves, since moving the coordinates never changes a noise's range. range_choice: the union of both branches; both branches are evaluated on every lane, and the choice is a select. The bounds drive the corner-column ranges (§5.4), the wetness early-out (§6.5) and parts of the layout validator (§6.6).

3.5 Interpreter

A batched Burst loop: one switch per instruction, and inside each case a loop over lanes. 2D lanes are one row of the padded column lattice (up to 86 lanes when a per-column output is evaluated for every column of chunk ± 27). Corner lanes are the active y corners of one corner column (at most 33 with cell height 8, 65 with cell height 4; in the 512-high world of H1 65 and 129, so H1 runs corner programs in slices of at most 128 lanes, AD-44). Voxel lanes are the voxels of one open cell (128 with cells 4 × 8 × 4). Scratch: 64 registers × 128 lanes × 4 bytes = 32 KB, allocated once per chunk (W2-ARC-03).

The lane loops only vectorise if the noise does. v1's SeededSimplex is scalar and branchy, so v2 needs a lane-wise simplex: one call per lane array, no branch per sample, and the same values as the scalar version the direct evaluation uses (W2-NG-03). It is the largest cost lever (§2.5).

3.7 Limits and fallback

Limits (start values): at most 512 instructions, 64 registers and 64 noises per graph, 16 octaves per noise, 16 points per spline and splines nested 8 deep. The graph validator rejects cycles, unknown names, missing required outputs and graphs over the limits, and names the file and node. It also rejects a noise whose octave table leaves the float range (a large gain or lacunarity over many octaves, a tiny wavelength) and a node whose bound is not finite, because its values could overflow and NaN would follow. A file nested more than 64 objects or arrays deep is rejected before it is read, and names are resolved and programs built without recursion, so a malformed file or a long chain of named nodes is an error, not a stack overflow.

V1 measures three things: (a) nanoseconds per simplex2 and simplex3 sample in the lane kernel, against v1's scalar call; (b) a test program shaped like terrain plus caves (2D, corner and voxel programs with markers) on real lane lengths, against hand-written Burst code for the same graph; (c) the dispatch overhead on an arithmetic-heavy graph with few noises. v1's climate fields alone would hide the dispatch cost, because both sides spend almost all their time in simplex calls. If the overhead in (b) is above +15 % (the top of the +5–15 % estimate given with DEC-126), an Editor step generates C# Burst code for the shipped graph, one statement per instruction of the flat program. The interpreter stays for mods and the preview, and a test compares the two bit for bit (W2-NG-03).

5.3 Cells and interpolation

The density is evaluated on a world-aligned corner lattice and interpolated trilinearly per voxel. Minecraft does the same: vanilla 1.21.4's noise_settings/overworld.json has size_horizontal 1 and size_vertical 2, and a cell is size_horizontal · 4 by size_vertical · 4 blocks, so its cells are 4 × 8 × 4 (Minecraft Wiki, “Density function”; vanilla data, §22). v2 starts terrain cells at 4 × 8 × 4 blocks (AD-06): 9 × 33 × 9 = 2,673 corners per chunk. Cells of 4 × 4 × 4 (9 × 65 × 9 = 5,265 corners) are measured in V2 and used only if 4 × 8 × 4 looks blocky on steep faces.

Measured in V2. Cells 4 × 4 × 4 cost about 0.02 ms more per chunk on the fixture (terrain 0.13 against 0.11 ms, §2.4). On the shipped graph they leave the heights unchanged and double the overhangs: 1.37 % of the land columns against 0.71 %, and 38 floating pieces against 15 in the 4096² window. The owner signed off the look with 4 × 8 × 4 cells (2026-11-22), so v2 keeps them; 4 × 4 × 4 is the cheap lever if later phases want more overhangs.

What is interpolated is set by the graph's interpolated markers (§3.3), each with its own cell height. Terrain and cave terms sit under separate markers, because P5 must tell terrain air (water below sea level) from carved air (dry, §9.1). The noises of the caverns and the lava pockets are interpolated on cells 4 high (DEC-155): their vertical detail (wavelength 14 for the hall detail, 8 for the lava pockets) is too fine for cells 8 high. Their bands, masks and the hall fold are applied per voxel, and the voxel program combines the cave terms per voxel (§10.1). Minecraft builds its noodle caves the same way: each noise sits in its own interpolated, and abs and max act per block outside it (vanilla 1.21.4 density_function/overworld/caves/noodle.json).

5.4 Skipping

  • Corner-column ranges. Each corner column gets a y range per field in which its corners are evaluated: terrain from preliminary_surface − Δdown to preliminary_surface + Δup (§5.1); each cave term from its band, mask and cover, tunnels from the cave floor to the top of the terrain range (§10). Each range is extended by one corner layer on both sides. Outside its range a corner takes the sign its bounds give: terrain solid below and air above; caves not carved.
  • Cells. For each field, a cell whose eight corners all lie outside their ranges and agree in sign is filled with that sign. Every other cell has all eight corner values computed, so the interpolation never mixes a computed value with a sign-only corner.
  • Uniform cells. Trilinear interpolation is a convex combination of the 8 corners, so when all 8 corners have the same sign, every voxel of the cell has that sign. Such cells are filled without per-voxel interpolation. The test is exact, not an estimate.
  • Tunnel cells. A tunnel is max(|a|, |b|) − r with a and b under separate markers (§10.3). If all eight corners have a > r, or all have a < −r (likewise for b), no voxel of the cell lies in the tunnel, by the same convexity argument.

6 · Biomes

Design rule (DEC-189): every biome must be one that could be found on Earth. It need not be fully realistic, but fantasy biomes and physically impossible landscapes are out where they can be avoided. Mod references (§18.7) count only where they look like real places.

6.1 Boxes

Per-biome parameter boxes (DEC-127), in Minecraft's format: a biome is placed by intervals per parameter (Minecraft Wiki, “Biome”). Each biome file holds one or more boxes; a box is an interval for T, F, C, E and W plus a depth interval. v2.0 evaluates depth 0 only; the depth interval is reserved for cave biomes (V8). A biome can hold several boxes, for example one inside the massif footprint and one outside.

6.2 Choosing a biome

  • Inside one data source (the base game or one mod) boxes must not overlap; an overlap is an error (AD-09). Across sources, the box of the later source in load order (the base game first) wins where boxes overlap, so a mod can add a biome without rewriting the base boxes; the validator reports the share of each box that a later box takes (DEC-157).
  • A point in no box takes the nearest box. The distance is the sum of the squared distances to each interval (0 inside it), unweighted; ties go to the order of the BiomeSet. Minecraft also takes the closest box outside all boxes; its exact distance form is not claimed here.
  • The choice reads only the climate parameters at depth 0, never the column height (AD-07).

6.3 Compiled lookup

The boxes compile into a grid whose lines are the box edges, so every grid cell lies inside one box or in a gap; one binary search per parameter finds the cell. A gap cell stores the boxes that can be nearest somewhere in the cell, and the column picks among them. If the grid would exceed 220 cells, a k-d tree over the box edges replaces it; a tree over 216 nodes (start value) is a validator error that names the files with the most edges. The lookup gives the brute-force result on every sampled point and costs at most 0.2 ms per chunk including padding.

Built in V3. The grid only: no k-d tree. A layout whose grid would exceed 220 cells is a validator error that names the files (the shipped layout needs far fewer). In-box cells hold the box of the latest source, then the lower box index; a gap cell keeps every box whose smallest distance to the cell is at most the smallest largest distance (with a relative tolerance of 10−4), and the outer gap cells reach to ±∞, so points beyond ±1 are exact too. Ties of the nearest box go to the lower biome id, then the lower box index. Tests compare the lookup with brute force on random layouts, sampled points and every gap cell (BiomeLayoutTests).

Uniform cells. When the four corners of a 4 × 4 column cell lie inside the same box, by at least the bounds margin (AD-30), and no box that wins over it overlaps the bounding box of the four corners' parameters, the 16 columns take that box without a lookup. This is exact: a box is convex, and the bilinearly interpolated parameters of a column are a convex combination of the corners'.

6.5 Wetness and the dry-column rule

  • Wet column: the terrain is air at y 123, the top water layer (AD-08). The value at y 123 comes from the two corner layers around it (y 120 and 128 with 4 × 8 × 4 cells), interpolated the same way as in P4.
  • Early-out: a corner column with preliminary_surface − 128 > Δdown is surely dry; one with 120 − preliminary_surface > Δup is surely wet (§5.1). Only corner columns in between evaluate the two layers, and P4 reuses the chunk's own values. When the four corners of a 4 × 4 column cell are all surely dry or all surely wet, its 16 columns take that flag without interpolation (exact, as the uniform cells of §5.4).
  • Dry-column rule: when the lookup gives a water biome (a flag in the biome file; only Ocean in the shipped set) on a dry column, the column takes the nearest land box instead, by the same distance rule. A land biome on a wet column keeps its biome (lakes, rivers).
  • The near_water rule condition (§7.2) uses the same wet flags on the stride-4 corner grid: a wet column within 16 blocks, probed every 4 blocks (DEC-44).

Built in V3. The sure states use Δup = 64 · bound / factor and Δdown = min(32, Δup) from the terrain marker; undecided corner columns run the corner program at the two layers around y 123 and interpolate as P4 does. The dry-column rule uses a second lookup compiled from the land boxes only. near_water comes with the rules in V4. With the shipped layout no column needs the dry-column rule (the ocean boxes end where the land starts); BiomePassesTests checks it with a widened Ocean box.

7 · Surface rules

7.1 Lists

Minecraft chooses surface blocks with one rule tree of conditions and sequences (Minecraft Wiki, “Surface rule”). v2 uses rule lists (DEC-133), which are easier to read and to extend by mods:

  1. global-before (for example snow),
  2. the list of the column's surface-source biome (§12; AD-25),
  3. global-after (for example a mod's fallback).

For each solid voxel the lists run in this order and the first rule whose condition holds acts. When no rule matches, the voxel keeps the default block (stone). A rule is a name, a condition and an action. Names are unique within a list; a mod inserts a rule before or after a named rule, appends it, or replaces a rule by name (AD-29, §14). Rules see the final solid mask after P4, so cave walls and the undersides of overhangs are surfaces like any other.

  • bands: strata by y. The band number is ⌊(y + shift) / period⌋ with a warped shift, and the block is the palette entry at that number modulo the palette length (v1's band palette, GEN-42 and DEC-85; start: period 7, thickness 2, warp 4 at wavelength 64).
  • sequence: a nested list; its first matching rule acts. If none matches, the outer list goes on.
  • condition: a nested rule with its own condition and action.

7.5 Cost

  • Column-constant conditions are evaluated once per column into a bitmask.
  • The rule depth R is the deepest stone-depth bound of any rule, noise included. A voxel that lies more than R below the nearest non-solid voxel above it and more than R above the nearest one below it is an interior voxel.
  • Interior voxels take the column's interior plan: the rules resolved once per column for interior voxels, at most four y ranges, each with a block or a bands action (more is a validator error, §7.6). Only voxels near a surface run the full lists.

Built in V4. The interior plan sorts the column's y thresholds (at most three, so four ranges) and walks the interior graph once per range, lazily; InteriorPlan_EqualsFullEvaluation_OnEveryVoxel compares it with the full graph on every voxel of the sample chunks. The full graph runs within Rabove of a run's top and Rbelow of its bottom; the Δdown margin of the top rules adds Rabove to the column's window (AD-31). Cost: §2.4.

7.6 Rule validator

  • Unknown blocks, biomes, noises or outputs: error, with the file and rule named.
  • A condition that can decide interior voxels must be column-constant or a y threshold; anything else is an error.
  • An interior plan that needs more than four y ranges: error, with the biome and the rules named.
  • Two rules with the same name in one list, or a before or after anchor that names no rule: error.
  • The caverns' cover (§10.2, Δdown + 8) must be at least the top rules' margin (Δdown) plus R, so a covered cavern never opens inside the top rules' reach. With the start values this means R ≤ 8: error otherwise.
  • A rule after an unconditional rule in the same list can never act: warning.

8 · Snow, ice & tree line

8.1 Effective temperature

T_eff(x, y, z) = T(x, z) − L · max(0, y − y_sea) + w(x, z)      (y_sea 124; 127 from H2, lapseFrom)

w = w_snow for snow, w_ice for ice (own noises, as in v1)

Snow and ice follow the climate temperature cooled with height, in every biome (DEC-130, DEC-131). This is an own extension: Minecraft uses each biome's base temperature, lowered with height above a fixed level (Minecraft Wiki, “Biome”). It has the form of v1's SurfaceCover temperature (GEN-36): climate temperature, a lapse above the water and a freeze noise once per column. T and the wobbles are column values; only the lapse is per voxel.

8.2 Snow

The snow rule sits in global-before: a floor voxel that is dry and sky_open, with Teff < Tsnow, in a biome without the never-snow flag, takes the snow block (shipped: Snow; a biome file may name its own). Since DEC-178, DEC-180 and DEC-181 the rule has five branches, in order, so steepness decides between rock and snow and height only moves the line. A steep floor (rise ≥ 4) is bare rock. A ledge (rise 2–3) is rock with a snow layer on it, and the four voxels under a snowy ledge or face are rock too (snow_rock_under). Above the tree line the floor is a snow block. A 1-block step (rise 1) is a snow block too, so no dirt side shows under the snow. On flat ground below the tree line the floor takes the biome's under block (no grass grows under snow), and a snow layer lies on the air voxel above it: a voxel 1/8 block high without collision, as in Minecraft. Since DEC-205 the snow blocks above the tree line and on steps carry the same layer, so every snowy step is one clean voxel high, and the foot of a step (step_foot: a direct neighbour lies higher) is a snow block under a half-high layer std:SnowLayerHalf (no collision either), so a 1-block step reads as two half steps. The foot rule comes after the cliff and ledge branches; a step across the chunk border keeps the thin layer. Snowy rock is a mix of the biome's rock and the darker std:StoneGrey wherever the graph output rock_mix (simplex, wavelength 12, 2 octaves) is ≥ −0.3, about 80 % dark in small patches (DEC-184); steep and alpine rock mix the same way in every biome but Desert and Badlands, whose rock is sandstone (DEC-182; Mountain-only at first, which left a light band where a Taiga or Plains slope meets the Mountain rock in tour round 5). No biome uses a snowy stone block any more (DEC-180). The look reference is the owner's picture of jagged dark peaks with white ledges (§18.7). Start values (AD-12), set so that the median Mountain temperature of the starting layout (about 0) keeps v1's snow line of 210 ± 6:

  • L = 0.0055 per block; Tsnow = −0.473; snow wobble wsnow ±0.033 (±6 blocks) at wavelength 48, v1's snow-line noise.
  • The snow line is ys(T) = ysea + (T − Tsnow) / L (ysea 124; 127 from H2). From H2 L is scaled with the relief (DEC-218); the wobbles stay in temperature units, so in blocks they grow by the same factor.

8.3 Ice

In the fluid pass, the top water layer (y 123) freezes where T + wice < Tice = −0.6, v1's freeze temperature 0.2 in the v2 range (AD-13). The ice wobble wice is ±0.08 at wavelength 24, v1's freeze noise (0.04 in v1's [0, 1] range); it gives the ice a ragged edge. With the V3 start values Tice + 0.08 ≤ Tsnow − 0.033 (−0.52 ≤ −0.506), so every frozen shore also carried snow down to the water, as v1's GEN-36 asks. The refit Tsnow = −0.638 (DEC-175) breaks that order; the owner kept Tice = −0.6 and made W2-CLM-05 a warning (DEC-176), so water may freeze along a shore without snow. Built in V4: sea ice covers 0, 9.87, 0, 4.24 and 0.35 % of open water on the five seeds. The FreezesWater flag goes (DEC-131 replaces DEC-65).

Frozen rivers (V5, DEC-207). Minecraft's Frozen River covers the river completely where the temperature is at level 0 (T < −0.45). v2 has no River biome (DEC-132), so the ice step takes a second test: water where the graph's river output is at least riverIceMin (shipped 0.01, so the whole valleys slice) freezes where T < riverIceTemperature (shipped −0.45), without the wobble, so a cold river is one sheet. The sea keeps Tice −0.6 with its wobble. Both settings sit in the climate block; without riverIceTemperature rivers freeze like the sea. Measured (SnowReport_FiveSeeds, snow.txt): river water freezes on 9.3, 9.1, 1.2, 27.6 and 8.6 % of its samples on the five seeds (the sea rule alone: 1.2, 2.8, 0, 20.2, 1.3 %); open water as a whole 0.49, 9.95, 0.10, 5.15, 1.14 %. As expected from DEC-176, most frozen rivers run between snowless banks: of the frozen river samples with a dry neighbour, 2.3, 28.3, 0, 62.1 and 7.6 % have a snowy one. Minecraft's frozen river always has snowy banks because the biome itself is cold; here the owner decides in the V5 check whether Tsnow or the river limit moves.

8.4 Never-snow biomes

  • A biome file may carry a never snows flag (shipped: Badlands, Desert, Savanna, Jungle). The snow rule and the ice skip a column whose surface-source biome has it, so snow and ice agree at a border. Both read the surface-source biome; v1's ice read the hard biome.
  • The flag is a filter, not the main tool: with the starting layout the hot band's snow line already lies above the terrain. The layout validator warns when a never-snow biome could reach its snow line: when ys(lowest T of its boxes) − 6 lies below the highest ground of its boxes, bounded by the interval rules. Such a biome would show a hard snow edge at its border.
  • The world report checks snow in never-snow biomes (0) and counts hard snow edges.

8.5 Tree line and meadow

  • Ttree = Tsnow + 15 · L ≈ −0.39: the tree line lies 15 blocks below the snow line, with its own wobble of ±8 blocks at wavelength 64 (v1's VEG-51 values). At T 0 it lies at 195, as in v1 (DEC-86). The below_tree_line condition (§7.2) reads this line.
  • The tree line never lies below y 170 (DEC-139, start value): ytree = ⌈max(170, ysea + (T − Ttree) / L + its wobble)⌉ (from H2 the floor and the gap to the snow line scale with the relief, DEC-218, about 214 and 28); the floor applies after the wobble (built in V4, AD-35), so the wobble never pushes the line under 170. In cold land the forests reach up to 170 even where the snow line lies far lower. With the refit Tsnow (DEC-175) Ttree = −0.556.
  • Flora rules with StopsAtTreeLine stop above it. Below it, trees, fallen logs and boulders may stand on the snow block, so cold forests stay forests under snow (DEC-139, AD-26); small plants keep VEG-52 and grow neither on snow nor on bare stone.
  • Below the tree line a dry floor takes its biome's meadow block (GEN-44). On Mountain: meadow, then bare stone above the tree line, then snow above the snow line (DEC-88).

8.6 What changes against v1

  • DEC-65 is reversed. Snow and ice are no longer limited to Mountain: the coldest lowland (T below −0.473, about 6 % of the land with a T spread of about 0.31, measured offline) is snowy down to the sea, ice forms where T is below −0.6 (about 1.7 % of the land), and cold Taiga and Plains hills are snowy above about 156. Their forests keep their trees under the snow (DEC-139). Massifs differ by band: those in the hottest T band, about a fifth, never carry snow, and those in the coldest band are white from about y 157 down to their foot. The owner confirmed this spread (DEC-152); the world report shows the snow share per T band (§13.5).
  • DEC-96's snow allowance in Badlands goes: Badlands never snows.
  • The fixed snow line (210 ± 6) and tree line (195 ± 8) become climate lines that pass through 210 and 195 at T 0; the tree line never drops below 170 (DEC-139).

9.2 Rivers

Rivers are Minecraft's valleys (DEC-132): the valleys slice of PV (PV ≤ −0.85, which is |W| ≤ 0.05) gets a low offset in the terrain splines (Minecraft Wiki, “World generation”). In v2:

  • Where the land around is low, the offset spline lowers S in the valleys slice to 3–5 blocks below sea level, and the fluid rule fills the bed with water.
  • Where the land is high, the valley stays above sea level and dry: a gorge without water (AD-14, DEC-141). There is no water above sea level.
  • No River biome: a river column keeps its land biome (a land biome on a wet column keeps it, §6.5). The river output, clamp(1 − |W| / 0.05, 0, 1), lets rules and mods dress the banks and the bed.
  • Start: rivers about 550 blocks apart (553 measured offline along a line). Their width follows the slope of W at its zero line, so it varies: across the valleys slice, measured offline, the median is 21 blocks, p10 13, p90 42 and p99 107, and the slice covers 7.2 % of the area. The world report prints the width percentiles, and V5 sets a width target with the owner.
  • Rivers are closed contours of one noise at sea level: no sources, no tributaries, no flow direction. Minecraft's rivers have the same form (Minecraft Wiki, “World generation”). A lever for a constant width: a river value from W² < h² · |∇W|² (half width h, no square root, the gradient from the stride-4 lattice).

  • Shape: v1's halls (CAV-10, DEC-79): one simplex octave at wavelength 96 across and 48 up, sampled at a position that two warp noises (wavelength 64) shift by up to 20 blocks in x and z, plus a detail octave (wavelength 28 across and 14 up, amplitude 0.3) folded at its zero crossings (1 − 2|n| − 0.3). The noises are interpolated on cells 4 high; the fold, the band and the mask act per voxel (DEC-155).
  • Height band: y 4…90 (y 4…93 from H2: the band moves with the sea, AD-43). The threshold rises towards the top of the band and falls towards its floor, so caverns close off at the top and are widest just above the floor (DEC-75, DEC-76). In the graph this is a y_gradient.
  • Mask: a 2D noise lets caverns form on about 28 % of the area: the shipped threshold, 27.7 % measured in v1 (DEC-150). Its edge fades linearly over 0.1 of mask value, as v1's FadeRaise (DEC-67).
  • Cover: caverns carve only below preliminary_surface − Cover. Start: Cover = Δdown + 8, so at least 8 blocks of rock lie over a cavern (v1's Cover 8).
  • Entrances: an entrance mask on about 3 % of the land (v1's share) lifts the cover and raises the band's top to preliminary_surface (a lerp on the mask in the y_gradient), so a hall grows up to the surface and opens to the sky there: rare, large cave mouths (DEC-55, DEC-153). Without the raised band a hall would close at least 34 blocks under the lowest dry ground (band top y 90, dry land from y 124; 93 and 127 from H2). v1 used this mask for worm shafts; v2 has no worms.
  • v1's pillars go. A mod or a later round can add them back as a graph term.

10.3 Tunnels and passages

  • Tunnels: max(|a|, |b|) − r, with two 3D noises a and b, one octave each at wavelength 64 (start, AD-15). They have no band and no mask: tunnels run from the cave floor to the surface. A tunnel follows the line where both noises are zero, so it winds through the rock and crosses other tunnels and caverns. This is the spaghetti form that DEC-54 did not choose in v1; the owner's pick of noise caves now takes it.
  • Radius: given in blocks, varied by a slow noise. Start: at least 2.5 blocks, so the player can walk through. The width in blocks is r / |∇noise| and varies along a tunnel, so the compiler converts the radius to a noise value with the noise's mean slope at its zero line.
  • Interpolation: interpolating the whole expression breaks thin tunnels into beads, because the trilinear interpolant of the V-shaped valley along the tunnel line is lowest at the cell corners. Measured offline (wavelength 64, 128³ blocks; design review of v1.1): radius 2.5 on cells 4 × 8 × 4 keeps 35 % of the carved voxels, in 134 pieces against 12; radius 4 keeps 67 %, in 46 pieces against 14; on cells 4 high, 59 % and 87 %. With a and b under separate markers and abs and max per voxel, radius 2.5 on cells 4 × 8 × 4 carves 104 % of the voxels in 14 pieces. V6a measures three options, and the owner picks (DEC-143, DEC-151): radius about 4 on cells 4 × 8 × 4; an own cave lattice with cells 4 high; a and b interpolated separately with abs and max per voxel.
  • Surface: tunnels have no cover and may break dry ground anywhere (DEC-77). They stop at water like every cave.
  • Passages (optional): the same form with a smaller radius under a mask. Off in the start graph.

10.4 Lava

  • Lava pockets (DEC-56): inside the lava mask (a 2D noise on about 59 % of the area: the shipped threshold, 59.3 % measured in v1, DEC-150; CAV-30), a flat 3D noise (wavelength 32 across, strongly squashed in y) carves in the band y 3…10 (CAV-31). v1 evaluated it per voxel; v2 interpolates it on cells 4 high and applies the band and the mask per voxel (DEC-155). The fluid rule makes their voxels at y ≤ 5 lava and those above air: a lava surface under a low air gap. The mask fades over 0.1 (DEC-67), and the pockets stay under the caverns' cover (DEC-68).
  • Lava level: every carved voxel at y ≤ 5 is lava, in every column (DEC-77, AD-02).
  • Lava emits light as before; the light job is measured again on lava chunks (CAV-50).

10.5 Connected caves

DEC-74's goal stays: no tunnel on its own. Noise tunnels are long lines that cross each other and the caverns, so they form networks without connector logic. The cave report checks this: the share of carved voxels in a sample window that belong to a component of at least 1,000 voxels or reach the window's edge (start target ≥ 95 %, a placeholder).

10.6 Ores

v1's ore veins stay (CAV-40, CAV-41, DEC-59): 16³ cells, hashed vein seeds and short random-walk blobs. The ore rules run in list order and each replaces only its host block (DEC-69). They now run after the fill and the surface rules (P6, AD-16), so they see the final blocks. Ores never replace air, so caves still expose veins in their walls, as in v1, where the ores came before the caves.

10.7 Bedrock

Unchanged (CAV-42): y 0 is always bedrock, y 1 and y 2 are bedrock where a 3D hash falls below 0.5 and 0.25.

What changes against v1: worms, connector worms, worm shafts and pillars go (DEC-134 replaces DEC-54, 57, 66, 70, 71, 73, 75 and 76). Tunnels now come from noise, the option DEC-54 left out. Caves near water follow DEC-78 (AD-03).

11 · Flora

11.1 Anchor

A column's flora anchor is the top of the terrain: its highest voxel with terrain density above 0 (§5.6). Flora grows there only when that voxel is not carved, and a tree only when the voxel under its trunk is solid (v1's CAV-04). v2.0 grows no flora on cave floors or under overhangs; that is an idea for V8 (AD-18).

11.2 Ring search

A tree anchored in the flora padding (11 blocks) is stamped by every chunk it reaches. So each chunk needs, for the 1,892 columns of its padding ring (54² − 32²), what the owning chunk knows about them. The ring search uses the same pure functions as the owning chunk (W2-ARC-04), in this order:

  1. Pre-filter: v1's MayBeMultiBlock test drops every ring column that cannot hold a multi-block plant; only the rest go on.
  2. Anchor: the column's terrain density between preliminary_surface − Δdown and preliminary_surface + Δup, where its top must lie, from the same world-aligned corners.
  3. Carved test: the cave density at the anchor voxel; a carved anchor grows nothing (§11.1).
  4. Top block: the surface rules for that one voxel, so the soil check reads the block the owning chunk places.
  5. Tree line and snow at the anchor (§8.5).

It therefore finds the anchor, and what flora needs to know about it, exactly as the chunk owning the column does. Cost: 0.2–0.4 ms (§2.4).

11.3 Rules

  • Species, densities, groves, clearings, boulders, fallen logs, water plants and the exact density pre-filter stay as they are (DEC-30…33, 45, 83, 84, 91, 97, 98).
  • The flora weights come from DistanceBlend, so the flora roll stays apart from the surface pick (DEC-04).
  • The tree line comes from the climate (§8.5). The ground checks (soil, height above water) read the final blocks.
  • DEC-72's test tiers stay; whether the flora fixture still turns caves off is decided in V6b.

15 · Determinism & identity

  • Pure function: every voxel, biome id and flora placement depends only on the seed, the position and the merged data (R3). The jobs keep FloatMode.Strict and synchronous Burst compilation (GameSpec §3.7).
  • No transcendental functions: GameSpec §3.7 found the worms' sin, cos and atan2 to be the only functions in shipped generation without a cross-machine promise. They go with the worms. v2's nodes are built from add, sub, mul, min, max and abs, and the noises add floor; code outside the graph may also divide and take square roots. IEEE 754 defines all of these exactly.
  • Compile-time arithmetic: the compiler does no float arithmetic in managed code (AD-30, §3.4), so the Editor and a player fold constants and bounds to the same bits.
  • Identity: a world stores generatorVersion 2 and the settings hash, a hash of the canonical JSON (sorted keys) of the fields marked as generation data in the merged data, so changing a colour or a display name never changes it; and a palette of biome names for its stored biome ids (§6.8). Land that was never edited follows the generator; edited chunks are saved (the D2 save model).
  • Hashes from the start: V1 adds a hash of the 2D outputs over fixed columns, and V2 a voxel hash over fixed chunks, both checked in the Editor; the player check rides on the first build that happens anyway.
  • Golden hashes (V7) extend them: the voxel hashes of a fixed set of chunks per seed (caves on, several biomes), checked in EditMode and in a development player on Windows and Linux (GameSpec §3.7). A change that moves them must be intended, and its PR updates them.

20.4 Flags for the owner

These results change or reverse something the owner signed off. They stand with the v2 picks unless the owner says otherwise. The owner's answers of 2026-11-21 (DEC-139…160) are noted where they apply.

  1. DEC-65 is reversed (DEC-130, DEC-131). Snow and ice follow the climate in every biome without the never-snow flag: the coldest lowland (about 6 % of the land at the start values, DEC-152) is snowy down to the sea, cold Taiga and Plains hills are snowy above about 156, and cold shores freeze (§8.6). The owner chose snowy forests (DEC-139): trees keep growing in the snow, since the tree line never lies below y 170.
  2. DEC-96's snow allowance is gone: Badlands never snows.
  3. DEC-54 is reversed (DEC-134). Tunnels come from noise, the form DEC-54 left out; worms, worm shafts and pillars go.
  4. DEC-78 holds over the cave design: water is never carved, so a cave can open a lake bed or the seabed and leave a wall of standing water. The world report counts the walls, and the owner judges them in the V6a tour (DEC-140); CaveWaterMargin is the lever (AD-03).
  5. DEC-77 holds over the lava mask: every carved voxel at y ≤ 5 is lava in every column; the mask only shapes the pockets above (AD-02).
  6. DEC-06 is dropped: continentalness no longer bends temperature and humidity (AD-04).
  7. DEC-38: there is no height stage any more, because the terrain does not depend on the biome. DistanceBlend remains for materials and flora; with the 4 largest weights per column (AD-28) the plan counts 0.3–1.0 ms for its kernel, measured in V3 (DEC-158).
  8. Tree line: v1's fixed line at 195 ± 8 becomes a climate line 15 blocks below the snow line, with its own ±8 wobble; at temperature 0 it still lies at 195, and it never drops below 170 (AD-12, DEC-139).
  9. DEC-120, 121 and 123: their classifier values (the Badlands height floor, the class-height peaks, the Ocean flag) are not carried over. The climate wavelengths of the shipped settings, which DEC-121 made larger, are only the start values of the sweep (AD-10). Their goals become world-report targets (§13.5).
  10. Part III research is parked with Biome-first (DEC-137): DEC-28 waits with it, and DEC-92 loses its subject.
  11. DEC-74's goal stays: no tunnel stands on its own; the cave report checks it (§10.5).
  12. DEC-72 (flora tests without caves) is decided again in V6b.
  13. DEC-27, DEC-110 (interval store) and DEC-46 (light on forest terrain) are measured again in V2 and V6a, since overhangs give these passes more work.
  14. Implausible pairs become an error of the layout validator instead of a preview overlay (§6.6).
